1. Executive Summary

This report evaluates the latency and throughput trade-offs of offloading AES-128 cryptographic workloads to an FPGA coprocessor via AXI DMA, comparing a register-level custom driver against the official Xilinx Standalone BSP driver. Measurements span 16 Bytes to 8 Kilobytes, each averaged over N = 200 bare-metal iterations:

  • The custom driver cuts software dispatch overhead by 2.32× (1.529 μs vs. 3.540 μs) versus the Xilinx Standalone BSP driver, by eliminating BSP-side validation and ring-pointer bookkeeping.
  • This translates into a ~10% throughput gain for small payloads (≤ 256 B). In this range, however, pure CPU-side AES execution remains competitive or faster, since fixed DDR row-activation, cache-maintenance, and AXI handshake overhead dominates at small transfer sizes.
  • For bulk streaming (≥ 4 KB), hardware acceleration reaches a measured 1.71 Gbps sustained (a ~6.6× speedup over a cited CPU-software AES baseline), while the driver-level optimization's contribution shrinks to <0.3% as memory-interconnect bandwidth becomes the dominant constraint.

3.1 Methodology & Measurement Limitations

How this was measured: All timings were captured on bare metal (no OS jitter) using Xilinx's XTime_GetTime(), which reads the ARM Cortex-A9 Global Timer (325 MHz), bracketed by dsb sy / isb barriers to prevent instruction reordering across the measurement window. Each value below is the mean of N = 200 back-to-back iterations.

Limitation This method is not cycle-accurate — Global Timer read latency and access overhead impose a small, fixed measurement floor. It is, however, highly consistent run-to-run, which is what this report relies on: the primary claim under test is the relative difference between the custom driver and the Xilinx BSP driver, not an absolute cycle count.

3.4 Theoretical vs. Physical Ceilings & Resume Reconciliation

  1. AES IP Pipeline Silicon Ceiling: 128-bit @ 75.0 MHz = 9.600 Gbps (1,200 MB/s; pipeline latency 21 cycles ≈ 280 ns).
  2. AXI HP0 Memory Bus Physical Ceiling: 64-bit @ 75.0 MHz = 4.800 Gbps (600 MB/s).
  3. Measured Peak Sustainable Rate: 1.71 Gbps (213.4 MB/s) — includes full bidirectional round-trip traffic across the shared HP0 DDR port (MM2S read + S2MM write competing for DDR arbitration), plus AXI-Stream width conversion and cache-maintenance overhead.
  4. Resume claim guidance: a 15 Gbps figure would represent an unconstrained, parallel-core ASIC implementation at >120 MHz — not this platform. On this Zynq-7000 SoC, the verified, defensible figure is 1.71 Gbps sustained (4.80 Gbps theoretical bus ceiling). This is the number to carry forward, not the earlier assumption.

4. Key Architectural Insights

4.1 The Utility Window Paradox

Driver optimization delivers measurable gains strictly at small payloads (≤ 256 B). Past 1 KB, hardware bus transfer latency grows roughly linearly with payload size while software arming time stays fixed. By 8 KB, saving 2.01 μs of software overhead yields only a ~0.26% throughput improvement — driver-level optimization becomes statistically negligible at that scale.

4.2 The Small-Payload Dilemma

Comparing against a software-AES baseline on the ARM Cortex-A9 (≈20 cycles/byte ≈ 260 Mbps ceiling)† puts the architectural break-even point at roughly 180–200 Bytes:

  • Below ~200 Bytes: software AES on the CPU core outpaces the DMA path — fixed DDR row-activation, cache-invalidation, and AXI handshake overhead exceeds the cost of doing the arithmetic directly.
  • Above ~200 Bytes: hardware acceleration decisively wins, reaching up to 6.6× the CPU's throughput at 8 KB while freeing the Cortex-A9 core entirely.

† Cited reference figure for Cortex-A9 software AES throughput; not independently measured in this test.

4.3 Interconnect Ceiling Analysis

Throughput plateaus at 1.71 Gbps, below the theoretical 4.80 Gbps AXI HP0 limit. This is due to half-duplex port arbitration: MM2S (read) and S2MM (write) share a single 64-bit HP0 slave port, reducing the practical bidirectional limit to 2.40 Gbps. The achieved 1.71 Gbps represents 71.2% bus utilization efficiency, with the remainder consumed by DDR row turnarounds and cache-maintenance routines.

5. Architectural Recommendations

1. Low-Latency MMIO Path for Small Packets (≤ 256 B)
A direct register-mapped AXI-Lite/FIFO interface to the AES core would bypass DDR3 round-trips and cache-maintenance overhead entirely for short command frames.
2. Coherent Interconnect via AXI ACP
Migrating DMA transactions from HP0 to the Accelerator Coherency Port (ACP) would let hardware cache-snooping (via the ARM SCU) eliminate the software flush/invalidate penalty.
3. Scatter-Gather Ring Buffers for Bulk Streaming
Moving from one-shot simple DMA transfers to circular Scatter-Gather descriptor queues would pipeline transfers continuously and remove per-packet CPU arming overhead.
